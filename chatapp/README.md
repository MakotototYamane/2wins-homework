# Chat App

LINE 風の簡易チャットアプリです。ユーザー名を入力して入室し、同じルームにいる人とメッセージを送り合えます。

| | 使用技術 |
| --- | --- |
| フロントエンド | Next.js（TypeScript） |
| バックエンド | FastAPI（Python） |
| データベース | SQLite |

## 機能

- **ログイン画面**: ユーザー名を入力して入室します。初めての名前なら自動で登録され、同じ名前なら同じユーザーとして入室します
- **チャットルーム画面**
  - メッセージの送信
  - メッセージ一覧の表示（自分は右側・緑、他の人は左側・白の吹き出し）
  - 2 秒ごとに新しいメッセージを自動で取得
  - 退室（ログイン画面に戻る）

## 起動方法

必要なもの: Python 3.11 以上、Node.js 20 以上

### バックエンド

初回のみ、仮想環境を作ってライブラリを入れます。

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate      # Windows の場合は .venv\Scripts\activate
pip install -r requirements.txt
```

起動します。

```bash
cd backend
source .venv/bin/activate
uvicorn main:app --reload
```

- 行の先頭に `(.venv)` が付いていれば、仮想環境が有効になっています
- `--reload` を付けると、ファイルを保存するたびに自動で再起動します
- 初回起動時に `chat.db`（データベースのファイル）が自動で作られます
- http://localhost:8000/docs を開くと、API をブラウザから試せます

### フロントエンド

バックエンドを起動した状態で、**別のターミナル**で実行します。

```bash
cd frontend
npm install      # 初回のみ
npm run dev
```

http://localhost:3000 を開きます。別のブラウザやシークレットウィンドウで別の名前で入室すると、やり取りを確認できます。

### 停止

それぞれのサーバーを起動したターミナルで `Ctrl + C` を押します。仮想環境から抜けるときは `deactivate` を実行します。

## 設計

### データベース

```
users                         messages
---------------------------   -------------------------------------
id    INTEGER  主キー（自動）   id       INTEGER  主キー（自動）
name  TEXT     重複不可         user_id  INTEGER  users.id を参照
                              content  TEXT
```

- メッセージには送信者の名前ではなく `user_id` を保存し、名前は `users` テーブルと JOIN して取得します。同じ情報を 1 か所にだけ持つことで、ユーザー情報が変わっても 1 か所の更新で済みます
- `users.name` は重複不可（UNIQUE）にしており、同じ名前のユーザーは 1 人だけです

### API

| メソッド | パス | 説明 |
| --- | --- | --- |
| POST | `/api/login` | ユーザー名で入室します。存在しなければ登録し、ユーザー情報を返します |
| GET | `/api/messages` | メッセージ一覧を古い順に返します（送信者の名前付き） |
| POST | `/api/messages` | メッセージを送信します。存在しないユーザーの場合は 404 を返します |

例:

```
POST /api/login       {"name": "taro"}                      → {"id": 1, "name": "taro"}
POST /api/messages    {"user_id": 1, "content": "こんにちは"} → {"result": "ok"}
GET  /api/messages                                          → [{"id": 1, "content": "こんにちは", "user_id": 1, "user_name": "taro"}]
```

- メッセージの取得と送信は同じ URL（`/api/messages`）にし、GET と POST で区別しています
- SQL に値を入れるときは必ずプレースホルダ（`?`）を使い、SQL インジェクションを防いでいます

### 判断したこと

- **簡易認証**: 要件が「ユーザー名で入室できる簡易的な認証」のため、パスワードは設けていません。ログインしたユーザーの id と名前はブラウザ（localStorage）に保存し、メッセージ送信時に `user_id` として送ります
- **新着メッセージの反映**: 2 秒ごとにサーバーへ一覧を取りに行く方式（ポーリング）にしました。仕組みが単純で、実装と動作確認がしやすいためです
- **入力チェック**: 空白だけの名前やメッセージは、画面側で送信しないようにしています

## 今後の改善案

- **認証の強化**: 今は `user_id` を書き換えると他人として送信できてしまいます。パスワードとトークンによる認証にすると防げます
- **リアルタイム化**: ポーリングを WebSocket に置き換えると、通信量を減らしつつ即座に反映できます
- **差分取得**: 今は毎回全件を取得しています。最後に受け取ったメッセージの id より新しいものだけを取得すると、メッセージが増えても通信量が増えません
- **複数ルーム**: `rooms` テーブルを追加し、`messages` に `room_id` を持たせると対応できます
- **サーバー側の入力チェック**: 空白だけの入力や長すぎる入力を、API 側でも弾くようにします
- **使い勝手**: Enter キーでの送信、新着メッセージへの自動スクロール、送信時刻の表示
